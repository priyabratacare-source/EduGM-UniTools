How it works

1

Load leniently

The damaged PDF is opened with pdf-lib's lenient parser, which skips malformed objects instead of failing outright.

2

Copy readable pages

Each page that can still be read is copied into a brand-new PDF document. Unreadable pages are skipped.

3

Save clean copy

The new document is saved with a fresh cross-reference table and valid byte offsets — a structurally clean file.

Frequently asked questions

Does my PDF get uploaded anywhere?

No. The entire repair process runs in your browser using pdf-lib. The file never leaves your device and no network request is made with its contents.

What kind of corruption can this fix?

It works best when the PDF's structure is damaged — broken cross-reference tables, missing trailer objects, or malformed page-tree references. In those cases the page content is often still intact, and copying pages into a new document bypasses the structural damage [citation:2][citation:9].

What can't it fix?

If the actual page content streams are physically missing, zeroed out, or overwritten, the page cannot be recovered — it will be skipped [citation:9]. Heavily encrypted files may also fail. This tool does not guess or fabricate missing content.

Why are some pages skipped?

pdf-lib tries to copy each page individually. If a specific page object is unreadable (for example, its content stream is truncated), that page is skipped while the rest of the document is still recovered. The report shows exactly how many pages were saved vs. skipped.

How large can the file be?

Up to about 100 MB. Very large files may take longer because every page is processed sequentially to keep memory use low.
